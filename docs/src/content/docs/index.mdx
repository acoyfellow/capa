Along with the upstream result, capa gives you a plain JSON receipt: what it called, what came back, and which checks passed. Keep it for logs, show it in a UI, or ignore it when you do not need it.

## Capabilities

capa already ships 14 generated bindings. [View Capabilities](/catalog/) for GitHub, Kubernetes, GitLab, Jira, Stripe, Box, Discord, Sentry, Slack, Twilio, Twitch, Zoom, and the rest. Generate one locally for your own API, or [contribute a capability](https://github.com/acoyfellow/capa/blob/main/CONTRIBUTING.md) if it belongs in the shared repo.

## Architecture

<div class="capa-flow" aria-label="capa call flow">
  <div class="flow-node">
    <strong>Caller Worker</strong>
    <code>env.&lt;NAME&gt;</code>
    <code>.ns.method()</code>
  </div>
  <div class="flow-edge">
    <span>JSRPC</span>
    <b>→</b>
    <small>result + receipt</small>
  </div>
  <div class="flow-node flow-node-wide">
    <strong>capa capability</strong>
    <code>WorkerEntrypoint</code>
    <code>fetchProof()</code>
    <code>act + assert</code>
  </div>
  <div class="flow-edge">
    <span>HTTP</span>
    <b>→</b>
    <small>upstream response</small>
  </div>
  <div class="flow-node">
    <strong>Upstream API</strong>
    <code>generated</code>
    <code>per spec</code>
  </div>
</div>

`fetchProof` makes the upstream HTTP call, runs the built-in checks plus any API-specific checks, and returns the response when those checks pass.

## Quick start

### 1. Deploy a capability

Click a **Deploy** button under [View Capabilities](/catalog/). Cloudflare clones the repo and deploys the Worker.

### 2. Set the API key

```bash
cd capabilities/<name>
wrangler secret put <SECRET_NAME>
```

### 3. Bind and call

```jsonc
// wrangler.jsonc
{ "services": [
  { "binding": "STRIPE", "service": "capa-stripe", "entrypoint": "StripeCapability" }
]}
```

```ts
const { result, evidence } = await env.STRIPE.charges.create({
  amount: 1000, currency: "usd", source: "tok_visa",
});
```
